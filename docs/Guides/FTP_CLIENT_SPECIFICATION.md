Данный документ представляет собой функциональную спецификацию встроенного FTP-клиента в Movian.

---

## 1. Спецификация конфигурации и авторизации (Configuration Specs)

FTP клиент получает параметры авторизации через `keyring_lookup()`, идентификатор
записи — URL вида `ftp://<host>:<port>` (`src/fileaccess/fa_ftp.c:232`, запрос
на `:239`).

| Параметр | Тип | Формат | Описание |
|---|---|---|---|
| `username` | Строка | UTF-8 | Имя пользователя. Значения по умолчанию нет. |
| `password` | Строка | Пароль | Пароль доступа. Значения по умолчанию нет. |

**Анонимного входа по умолчанию не существует.** Учётные данные всегда приходят
из связки ключей: при первой попытке `keyring_lookup` вызывается без
`KEYRING_QUERY_USER` и берёт сохранённое, при повторной — с ним, и пользователя
спрашивают. Если соединение помечено non-interactive, вторая попытка сразу даёт
отказ (`fa_ftp.c:236-237`), поэтому фоновое сканирование не может «зайти
анонимно» — оно просто не подключится.

## 2. Спецификация поддерживаемых операций VFS (VFS Operations Specs)

FTP-клиент Movian является **только читающим (read-only)**. Запись, удаление и создание файлов не поддерживаются.

| Функция VFS | FTP Команды (RFC 959) | Описание |
|---|---|---|
| `ftp_open` | `PASV`, `TYPE I`, `RETR <file>` | Открывает файл для чтения. Инициирует пассивное соединение и команду скачивания. |
| `ftp_close` | Close Data Socket | Закрывает сокет передачи данных. Возвращает командное соединение в пул. |
| `ftp_read` | Read Data Socket | Читает порции байтов из открытого сокета данных. |
| `ftp_seek` | `REST <offset>`, `RETR` | Выполняет позиционирование в файле. Требует закрытия и повторного создания канала данных со смещением `REST`. |
| `ftp_fsize` | `SIZE <file>` | Запрашивает точный размер файла на сервере. |
| `ftp_stat` | `SIZE`, `MDTM` или `STAT` | Запрашивает метаданные файла/папки (размер, дата модификации, тип). |
| `ftp_scandir` | `MLSD`, `LIST` или `STAT <dir>` | Получает список содержимого папки. Пробует современные расширения `MLSD` (RFC 3659), при отсутствии — откатывается на `LIST` или `STAT`. |

## 3. Таблица обработки ошибок FTP (Error Mappings)

Статусные коды ответов FTP сервера транслируются в UNIX-ошибки VFS:

| Код ответа сервера | Код ошибки VFS | Описание |
|---|---|---|
| `530 Not logged in` | `EACCES` | Ошибка авторизации. Инициирует системный запрос ввода пароля. |
| `550 File not found / Access denied` | `ENOENT` | Файл или каталог не найден на сервере. |
| `421 Service not available` | `ECONNRESET` | Сетевое соединение разорвано сервером. |
| `500 / 501 / 502 / 504` | `ENOTSUP` | Команда или параметр не поддерживаются сервером. |

## 4. Ограничения спецификации и лимиты (System Limits)

* **Таймаут подключения (Connect Timeout):** `5000` мс — командное соединение
  (`fa_ftp.c:210`) и соединение данных (`:342`) открываются одним и тем же
  вызовом `tcp_connect(..., 5000, 0, NULL)`.
* **Таймаут операций ввода-вывода (I/O Timeout):** Регулируется внутренними таймаутами сокетов `tcpcon_t`.
* **Кодировка символов:** По умолчанию используется UTF-8, если сервер подтверждает ее поддержку в ответе на `FEAT` (или отправляется `OPTS UTF8 ON`). При отсутствии поддержки серверные имена декодируются в ASCII/ISO-8859-1.
* **Позиционирование (Seek):** Операция seek является относительно медленной, так как требует разрыва старого TCP сокета данных, отправки `REST` по командному каналу и открытия нового TCP сокета данных.
