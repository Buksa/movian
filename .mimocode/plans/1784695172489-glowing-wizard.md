# Mechanism B — Исправление (issue #139)

## Проблема

Smoke runner обнаруживает wedge (504 на `/api/screenshot/raw`), **сразу** вызывает `stop_wedged_instance()` → `kill_owned_pid()` → SIGTERM. Внешний отладчик (GDB/DAP) не успевает attach — pid уже мёртв. Диагностические дампы всегда показывают "stopped-clean" с пустыми стек-фреймами.

## Решение

Добавить **auto-capture thread dump** внутрь wedge-пути smoke runner, **перед** `stop_wedged_instance()`. Capture — best-effort, timeout-bounded (5s), не блокирует stop path.

## Реализация

### 1. Новая функция `capture_wedge_diagnostics()` в `smoke.py`

```python
def capture_wedge_diagnostics(
    inst: Instance,
    bundle: Path,
    timeout: float = 5.0,
) -> None:
    """Best-effort GDB thread dump before killing a wedged process.
    
    Runs `gdb -batch -p <pid> -ex 'thread apply all bt full' -ex detach`
    with a timeout. Output saved to bundle/thread-dump.txt.
    Never raises — errors are logged but never block the stop path.
    """
    pid = inst.live_pid()
    if pid is None:
        return
    try:
        result = subprocess.run(
            [
                "gdb", "-batch",
                "-ex", "set pagination off",
                "-ex", "set confirm off",
                "-ex", "set print thread-events off",
                "-ex", "handle SIGPIPE nostop noprint pass",
                "-ex", "attach %d" % pid,
                "-ex", "info threads",
                "-ex", "thread apply all bt full",
                "-ex", "detach",
            ],
            capture_output=True,
            text=True,
            timeout=timeout,
        )
        dump_path = bundle / "thread-dump.txt"
        dump_path.write_text(
            "--- gdb stdout ---\n%s\n--- gdb stderr ---\n%s\n"
            % (result.stdout, result.stderr),
            encoding="utf-8",
        )
    except FileNotFoundError:
        # gdb not installed — skip silently
        pass
    except subprocess.TimeoutExpired:
        # timeout — process may be truly stuck, don't wait longer
        pass
    except Exception:
        # any other error — don't block stop path
        pass
```

### 2. Вставка в `_run_one()` (smoke.py:501-504)

**Было:**
```python
bundle = _write_bundle(inst, definition["name"], transcript, wedge)
stop_outcome = None
if wedge:
    stop_outcome = stop_wedged_instance(inst)
```

**Стало:**
```python
bundle = _write_bundle(inst, definition["name"], transcript, wedge)
stop_outcome = None
if wedge:
    capture_wedge_diagnostics(inst, bundle)
    stop_outcome = stop_wedged_instance(inst)
```

**Было:**

bundle = _write_bundle(inst, selected[0]["name"], transcript, True)

## Доказательство работоспособности

1. Запустить `mdev smoke run health` с намеренно застрявшим процессом (или подменить health check на 504)
2. Убедиться, что `thread-dump.txt` появляется в bundle **до** остановки процесса
3. Проверить, что `thread-dump.txt` содержит реальные стек-фреймы (не "stopped-clean")
4. Проверить, что timeout capture (5s) не блокирует stop path — процесс останавливается даже если GDB зависает
5. Проверить, что отсутствие `gdb` не ломает smoke runner (silent skip)

## Существующие паттерны GDB-интеграции

- `support/smb-smoke/run-gdb-smoke.sh:83` — `gdb -q --batch -ex "thread apply all bt full"` (аналогичный паттерн)
- `support/smb-smoke/run-http-nav-smoke.sh:56` — `gdb -ex r -ex "thread apply all bt full" -ex q`
- `ext/libyuv/tools_libyuv/valgrind/gdb_helper.py:34` — `gdb -batch -x %s`

## Архитектурные ограничения

1. **gdb может быть не установлен** — silent skip, не блокирует smoke
2. **Process может быть уже мёртв** к моменту capture — `live_pid()` вернёт None, skip
3. **GDB может зависнуть** — timeout 5s, subprocess killed by timeout
4. **SIGTERM от runner'а может прийти во время capture** — subprocess.run с timeout защищён от этого
